# Optional Peer Learning: Predict, Compare, Explain

This is one adaptable peer exchange for **Module 6**, not an extra project. Instructors may use it in Canvas, another discussion board, or a classroom. Replace the existing **Comparing AND vs OR** discussion/practice segment; do not assign both. Allow roughly **10 minutes of active work** across a flexible reply window. This estimate is provisional, not a required pace.

## Start with the Existing Example

Open [Module 6](../notebooks/06_multi_condition_logic.ipynb). In **Comparing AND vs OR**, use the first side-by-side example with `has_network = True` and `has_admin_permission = False`. It already contains all the code you need. No loops, lists, or new tools are required.

## Think Before You Run

1. Predict each printed result without running the cell. In one or two sentences, explain why `and` and `or` might differ.
2. Run the cell and compare the actual output with your prediction. If your prediction changed, explain what you noticed.
3. Post your prediction, observation, and short explanation. An initially incorrect prediction is useful evidence of learning, not something to hide.

## Compare with One Peer

Reply to one classmate with a specific point of agreement or a gentle correction and the reason. Suggest changing **one** Boolean value. Both learners can predict and run that case independently, then note what changed. Use synthetic values only; never share passwords or real account information.

Keep each learner's explanation in their own words. Discuss reasoning, not copies of assessed solutions. Follow the [AI guidance](ai_usage_guidelines.md); AI cannot replace your prediction, peer response, or reflection.

## Equivalent Solo Option

If you are learning independently, cannot join the discussion, or have no peer response by the deadline, compare your explanation with the notebook's explanation instead. Change one Boolean value, predict and run again, and write what the comparison clarified. Use the same time budget and, if assessed, the same completion credit; no attendance or peer-availability penalty.

## Instructor Setup

- Copy these instructions into one discussion prompt and link the original notebook rather than maintaining a second code example.
- Announce the initial-post and reply windows, solo option, help channel, and whether this replaces existing participation credit. Do not add a new grading category.
- Model a respectful reply such as “I interpreted this condition differently because…”. Give feedback on reasoning and observation, not agreement or speed.
- Keep the final project and other individually assessed work individual. This exchange does not authorize sharing complete assignment solutions.
