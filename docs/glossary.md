# Beginner glossary

Use this as an optional reference while working through the existing lessons.

| Term | Plain-language meaning |
|---|---|
| Variable | A name referring to a value, such as `score = 80`. Assigning again changes what the name refers to. |
| Assignment | Storing a value under a name with `=`. It is different from the equality comparison `==`. |
| Data type | The kind of a value: for example, text (`str`), a whole number (`int`), a decimal number (`float`), or `bool`. |
| Input | Information entered by a user. Python's `input()` returns text. |
| Output | Information a program shows, for example using `print()`. |
| Conversion | Changing a suitable value to another type, for example `int("3")`. Not every value can be converted. |
| Boolean | Either `True` or `False`. Comparisons produce Boolean results. |
| Condition | A check used to decide which code to run. |
| Indentation | Spaces at the start of a line that group code inside a decision, loop, or function. |
| Loop / iteration | A loop repeats instructions; one repeat is an iteration. |
| `range(n)` | Supplies integers from `0` up to, but not including, `n`. `range(3)` supplies `0, 1, 2`. |
| List / index | A list stores related items. An index selects an item by position; the first position is `0`. |
| Running total | A value updated as each new number is added, such as `total = total + reading`. |
| Function | A named group of instructions that can be called again. A parameter accepts an input value. |
| Syntax error | Python cannot understand the code as written, for example because a quote is missing. |
| Runtime error | An error during execution, such as using an undefined name. |
| Logic error | Code runs but does not give the intended result. Testing helps reveal it. |
| Edge case | A boundary or unusual input, such as a value exactly at a threshold. |
| Kernel / notebook cell | The kernel runs Python. A cell is one section of code or text in a notebook. Restarting the kernel clears its remembered variables. |
| Trace | A record of execution steps. The explorers highlight the line that runs next and show the state before it executes. |
